Synchronization

Sync Methods

MobileOrg supports three synchronization methods:

MethodConfiguration RequiredUse Case
WebDAVURL, username, passwordWebDAV-enabled cloud storage (e.g. Nextcloud, ownCloud) or HTTP server
SSHHost, port, username, password or key, remote pathRemote server accessible via SSH/SFTP (e.g. VPS, NAS)
SD CardLocal directory pathManage org files on the same device through other apps or file manager

Preparing the Server Side

The server side only needs a readable and writable directory containing: index.org (required), the org files to sync, and checksums.dat (for incremental comparison).

Emacs Workflow (standard): Use org-mobile (built into Emacs) to manage the server-side directory. Basic configuration:

(setq org-mobile-directory "~/mobileorg/")
(setq org-mobile-files '("~/org/home.org" "~/org/work.org"))
(setq org-mobile-inbox-for-pull "~/org/from-mobile.org")
  • org-mobile-directory: the server-side directory described above. For WebDAV, set it directly to the URL (e.g. https://dav.example.com/mobileorg/; Emacs has built-in DAV support for reading and writing). For SSH, Emacs does not support it directly — usually push to a local staging directory and then upload it to the server with rsync/scp. For SD Card, just use the directory path exposed on the device.
  • org-mobile-files: the list of org files to sync; defaults to org-agenda-files.
  • org-mobile-inbox-for-pull: required. When running org-mobile-pull, edits uploaded from the phone are first merged into this inbox file and then applied; without it pull does not work.

Commands: M-x org-mobile-push copies org-mobile-files to the server-side directory and generates index.org and checksums.dat; after syncing on the phone, run M-x org-mobile-pull to consume the edits from the phone.

Hand-written minimal index.org: Without Emacs, just write it by hand:

#+TODO: TODO DOING | DONE CANCELED
* 文件清单
[[file:home.org][Home]]
[[file:work.org][Work]]

Server-side requirements per sync method:

  • WebDAV: any WebDAV service with read/write (GET/PUT) support (Nextcloud, ownCloud, or self-hosted)
  • SSH: a server with writable SFTP access (password or key authentication)
  • SD Card: any local directory (files placed by other apps or a file manager)

Setup Wizard

To configure sync for the first time, go to Settings → Actions → Setup Wizard. After choosing a sync method, fill in the required fields:

  • WebDAV: URL must include the full path to index.org (e.g. https://cloud.example.com/mobileorg/index.org). The wizard automatically extracts the directory path for other files.
  • SSH: Remote path should also point to index.org (e.g. /home/user/org/index.org). Default port is 22. Authentication can use password or SSH private key (click button to select key file).
  • SD Card: Browse local storage and select the directory containing org files (must include index.org).

After configuration, click "Test Connection" to verify, then click "Done" to perform the first sync automatically.

How Sync Works

MobileOrg uses a bidirectional sync mechanism:

  1. Pull: Download index.org and checksums.dat from the server, compare checksums with local files, and only download changed files. Files removed from the server's index.org are deleted locally after sync.
  2. Parse: Downloaded org files are parsed by OrgFileParser into the local database, accessible via ContentProvider.
  3. Push: Local captures and edits enter the Edits queue. During next sync, they are merged into mobileorg.org and uploaded to the server. The local queue is cleared after upload.

See How It Works for the complete mechanism and file formats.

Config Import/Export

Go to Settings → Actions → Export Sync Configuration to save your current sync configuration as a JSON file using the system file picker (cloud storage recommended). After reinstalling the app, use Import Sync Configuration to select the file and restore all settings without re-entering them.

Troubleshooting

  • Self-signed Certificate Warning: When using HTTPS and the server's self-signed certificate changes, sync displays the CertificateConflict screen showing old and new certificate hashes. Choose "Accept" to update the stored certificate, or "Deny" to abort sync.
  • Sync Failure: Check the error message in the notification. Common causes include incorrect URL/path, wrong credentials, no network connection, or server permission issues.
