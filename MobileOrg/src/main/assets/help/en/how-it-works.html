How It Works

Local Copy Model

MobileOrg never touches your org files on the server directly. During synchronization the app pulls the org files from the server, parses them, and stores them in a local database; all browsing and editing afterwards happens fully offline with no network requests. Edits are not uploaded in real time either — they enter a local queue and are only uploaded at the next synchronization. Without a network connection the app works as usual; your changes simply stay local.

The Three Convention Files on the Server

The sync directory holds three files MobileOrg relies on by convention:

  • index.org: the file list and global configuration. A minimal example:
#+TODO: TODO DOING | DONE CANCELED
#+TAGS: work home learning
* 文件清单
[[file:home.org][Home]]
[[file:work.org][Work]]

Links of the form [[file:filename][alias]] list the files that take part in synchronization; the #+TODO: line defines the keywords available in the app (states before | are not-done, after it are done); the #+TAGS: line defines the available tags.

  • checksums.dat: one <checksum>␣␣<filename> per line (separated by two spaces, checksum first). The app compares local and remote checksums to decide which files need re-downloading.
  • mobileorg.org: the channel for uploading local edits (see below).

Uploading Edits

Local edits never modify the remote org files directly. At synchronization time, all pending edits and captures are serialized as org entries and appended to the end of the remote mobileorg.org (alias "Captures"), which is then uploaded; afterwards the local queue is emptied. On the Emacs side, run org-mobile-pull to digest these changes and merge them back into the original files.

When Synchronization Runs

  • The manual sync button on the main screen
  • The automatic sync interval configured in settings
  • Device boot

Cleanup of Remote Deletions

Files removed from index.org are deleted from the local database after the next synchronization; mobileorg.org (Captures) is not affected.

For setting up the server side, see Sync Configuration.
