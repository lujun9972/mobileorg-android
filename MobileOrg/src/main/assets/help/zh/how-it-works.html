工作原理

本地副本模型

MobileOrg 不直接操作服务器上的 org 文件。同步时，app 从服务器拉取 org 文件，解析后存入本地数据库；此后所有浏览与编辑都完全离线进行，不产生任何网络请求。编辑也不会实时回传——它们先进入本地队列，在下一次同步时才上传。没有网络时 app 一切照常可用，只是改动暂存在本地。

远端三个约定文件

同步目录下有三个 MobileOrg 约定的文件，各有分工：

  • index.org：文件清单与全局配置。最小示例：
#+TODO: TODO DOING | DONE CANCELED
#+TAGS: work home learning
* 文件清单
[[file:home.org][Home]]
[[file:work.org][Work]]

[[file:文件名][别名]] 形式的链接列出参与同步的文件；#+TODO: 行定义 app 内可用的关键字（| 之前是未完成态、之后是完成态）；#+TAGS: 行定义可选标签。

  • checksums.dat：每行一个 <校验和>␣␣<文件名>（两个空格分隔，校验和在前）。app 对比本地与远端校验和，据此判断哪些文件需要重新下载。
  • mobileorg.org：本地修改的回传通道（见下节）。

编辑如何回传

本地编辑不直接修改远端 org 文件。同步时，所有待上传的编辑与 capture 被序列化为 org 条目，追加到远端 mobileorg.org（别名 "Captures"）末尾并上传，随后本地队列清空。在 Emacs 端执行 org-mobile-pull 即可消化这些修改并合入原文件。

同步触发时机

  • 主界面的手动同步按钮
  • 设置中配置的自动同步间隔
  • 设备开机

远端删除清理

从 index.org 移除的文件，在下次同步后会从本地数据库中删除；mobileorg.org（Captures）不受影响。

配置服务端的方法见同步配置。
